# 大数据部门项目管理系统设计

## 1. 目标

为大数据业务部建立一个内部项目管理系统，使老板、部门负责人、PMO、项目经理和项目成员能够在同一处了解项目状态、项目进度、分阶段/分模块执行情况以及预算、成本、合同和回款信息。

第一阶段的核心结果是：

- PMO 能建立统一的项目台账。
- 项目经理能够持续维护项目及其阶段/模块进度。
- 管理层能快速识别正常、关注、延期项目。
- 项目财务信息可在项目维度汇总查看。
- 项目材料仍存放在 Seafile，系统保存并展示对应链接。
- 系统能识别并提醒周期内未更新的项目。

## 2. 范围

### 2.1 第一阶段包含

- 用户登录、角色和项目数据权限。
- 项目台账和项目生命周期。
- 项目下的一层阶段/模块分项。
- 分项负责人、计划时间、进度、权重和健康度。
- 里程碑、风险与问题。
- 周期状态更新和更新历史。
- 预算、成本、合同和回款信息。
- Seafile 文件夹链接。
- 管理驾驶舱和项目详情页。
- 未更新、逾期里程碑、超预算等管理提醒。
- Excel 导入，用于历史项目资料迁移。
- 操作审计和 PostgreSQL 集成测试。

### 2.2 第一阶段不包含

- 客户或第三方登录。
- 客户查询端。
- Seafile 文件复制、全文搜索或深度 API 集成。
- 企业微信、邮件等外部通知渠道；第一阶段先提供系统内提醒。
- 任意深度的任务管理；只保留一层阶段/模块，数据库预留 `parent_id`。
- AI 自动判断项目状态。
- 独立的取数适配器和指标平台能力。

## 3. 用户和权限

| 角色 | 权限 |
| --- | --- |
| 老板 | 查看全部项目、驾驶舱、进度、延期、风险和财务汇总；默认不编辑项目数据 |
| 部门负责人 | 查看部门项目；创建/调整项目；指定项目经理；处理重大风险 |
| PMO | 创建和管理全部项目；维护台账、更新规则和模板；检查逾期更新；导出汇总数据 |
| 项目经理 | 维护负责项目；管理成员、阶段/模块、里程碑、进度、风险和项目财务信息 |
| 项目成员 | 查看参与项目；更新分配给自己的分项、里程碑或问题；不能修改项目基线和财务信息 |

新项目只由 PMO 创建。项目访问范围由部门归属、项目负责人和项目成员共同决定：老板、部门负责人和 PMO 可按组织范围查看；项目经理查看负责项目；项目成员查看参与项目。

## 4. 核心业务模型

### 4.1 项目结构

```text
项目
├─ 阶段或模块
│  ├─ 负责人
│  ├─ 计划起止时间
│  ├─ 实际进度
│  ├─ 权重
│  ├─ 健康度
│  └─ 里程碑
└─ 阶段或模块
```

阶段和模块使用同一类“项目分项”模型，通过类型区分。分项保留 `parent_id`，第一阶段界面只展示一层，未来可支持模块下再拆阶段。

### 4.2 进度

项目经理维护各分项的实际进度。项目总进度由系统自动汇总，不允许直接手工覆盖：

```text
项目总进度 = Σ(分项实际进度 × 分项权重)
```

未设置权重时按分项等权计算。每次进度变更记录操作人和时间。

### 4.3 状态和健康度

阶段状态：筹备中、执行中、已完成、暂停、归档。

项目健康度：正常、关注、延期。

第一阶段使用可解释规则：

- 关键里程碑逾期未完成：延期。
- 项目计划结束日期已到但未完成：延期。
- 风险/问题超过截止时间未关闭：关注。
- 超过项目更新周期未填报：关注。
- 成本超过预算阈值：关注。

## 5. 主要流程

1. PMO 创建项目并填写基础信息。
2. PMO 指定项目经理；项目经理补充成员、阶段/模块、里程碑、预算、合同和 Seafile 链接。
3. 项目成员更新自己负责的分项、里程碑和问题。
4. 项目经理按默认每周一次的周期提交状态更新；周期可以按项目配置。
5. 系统汇总分项进度、风险、里程碑、财务和更新状态。
6. 老板、部门负责人和 PMO 在驾驶舱查看异常并处理重大风险。
7. 项目完成后由 PMO 归档。

## 6. 页面设计

### 6.1 管理驾驶舱

- 项目总数、正常、关注、延期数量。
- 项目总进度概览和排行。
- 即将到期项目/分项。
- 长期未更新项目。
- 预算、成本、合同、回款汇总。
- 重大风险与待处理问题。

### 6.2 项目详情

- 项目基本信息和 Seafile 链接。
- 项目总进度、状态和健康度。
- 阶段/模块进度表，可下钻查看里程碑。
- 风险与问题。
- 财务信息。
- 历史状态更新和操作记录。

### 6.3 项目经理工作区

- 我的项目。
- 待更新项目。
- 我的分项、里程碑和问题。
- 周期状态更新表单。

## 7. 技术架构

复用现有技术骨架：

```text
Vue 3 SPA
├─ 项目管理端
├─ 领导驾驶舱
└─ PMO 管理端
          │ HTTP /api
FastAPI 单体
├─ 认证鉴权 / RBAC / 数据权限
├─ 项目管理服务
├─ 进度、里程碑、风险服务
├─ 财务与合同服务
├─ Seafile 链接服务
├─ 提醒与审计服务
└─ Excel 导入服务
          │ SQLAlchemy
PostgreSQL
├─ sys_ 系统和权限
└─ pm_ 项目管理业务
```

前端采用 Vue 3、Vite、TypeScript、Element Plus、Pinia、Vue Router 和 Axios。后端采用 FastAPI、SQLAlchemy 2.x、Pydantic 2.x、JWT/RBAC。PostgreSQL 是正式数据源。

第一阶段不需要 Celery 等复杂任务队列；提醒计算可以先通过可复用的定时服务或管理命令完成。若部署为多进程服务，需要确保提醒任务只有一个调度实例。

## 8. 数据表建议

系统域：

- `sys_user`
- `sys_role`
- `sys_permission`
- `sys_department`
- `sys_audit_log`

项目域：

- `pm_project`
- `pm_project_member`
- `pm_work_item`
- `pm_milestone`
- `pm_status_update`
- `pm_risk_issue`
- `pm_budget`
- `pm_cost`
- `pm_contract`
- `pm_payment`
- `pm_file_link`
- `pm_reminder`

实际建表时应根据字段和查询场景合并过度细分的财务表，避免第一版模型过于复杂。

## 9. 错误处理和审计

- 所有写入接口校验角色、数据范围和字段合法性。
- 删除项目采用归档/软删除，不直接物理删除。
- 关键财务字段、项目基线、进度和健康度变更写入审计日志。
- 前端统一处理未登录、无权限、校验失败和服务错误。
- 重要计算规则在后端执行，避免仅依赖前端计算。

## 10. 测试和验收标准

### 10.1 权限测试

- 五类角色只能访问允许的数据范围。
- 项目成员不能编辑项目基线和财务信息。
- 非 PMO 用户不能创建新项目。

### 10.2 业务测试

- 分项进度能正确按权重汇总到项目总进度。
- 未设置权重时能按等权汇总。
- 逾期里程碑、逾期风险、未更新项目和超预算能触发正确健康度。
- 项目归档后不能继续提交周期更新。
- Seafile 链接能保存、展示和打开。

### 10.3 技术测试

- API 单元测试覆盖认证、权限、核心计算和状态流转。
- 使用真实 PostgreSQL 测试库覆盖事务、约束、日期和枚举行为。
- 前端类型检查和生产构建通过。
- 核心页面在桌面和常见笔记本尺寸下不出现信息遮挡。

## 11. 成功标准

第一阶段交付后，负责人能够在不查看多个项目文件夹、不临时拉会的情况下回答：

1. 当前有哪些项目，哪些正常、关注或延期？
2. 每个项目和其阶段/模块分别完成到什么程度，下一步是什么？
3. 项目的预算、成本、合同和回款情况如何？
4. 哪些项目长时间没有更新，哪些风险需要处理？

本设计不包含客户端和外部通知，先确保内部项目管理流程真实可用，再根据试用反馈扩展。
